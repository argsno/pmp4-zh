Chapter 7

卷积

常量内存与缓存入门

摘要

本章将卷积作为一种重要的并行计算模式来介绍。虽然卷积被用于计算机视觉和视频处理等许多应用中，但它也代表了一种通用模式，构成许多并行算法的基础。我们从卷积的概念讲起。然后给出一个基础并行卷积算法，其执行速度受限于访问输入元素和掩码元素所需的 DRAM 带宽。接着介绍常量内存，以及对核函数和主机代码做的一个简单修改，从而实际上消除了所有 DRAM 访问。随后是一个输入分块核函数，它消除了访问输入元素所需的大部分 DRAM 访问。我们还会说明，在较新的设备上，利用数据缓存可以简化代码。最后进入二维卷积核函数，并分析分块效果如何随一维和二维卷积的分块大小而变化。

卷积；卷积滤波器；分块；幽灵单元；光环单元；分块效率；常量内存；常量缓存

在接下来的几章中，我们将讨论一组重要的并行计算模式。这些模式是许多并行应用中出现的各种并行算法的基础。我们将从卷积讲起，它是一种常用的数组运算，以各种形式用于信号处理、数字录音、图像处理、视频处理和计算机视觉。在这些应用领域中，卷积常以滤波器的形式执行，将信号和像素转换为更理想的值。我们的图像模糊核函数就是这样一个滤波器，它平滑信号值，使人们能够看出整体趋势。再如，高斯滤波器是卷积滤波器，可用于锐化图像中物体的边界和边缘。

卷积在生成每个输出元素时通常会执行大量的算术运算。对于高清图像和视频这样包含大量输出元素（像素）的大型数据集，计算量可能非常巨大。一方面，卷积的每个输出数据元素都可以彼此独立地计算，这是并行计算的一个理想特性。另一方面，处理不同的输出数据元素时存在大量的输入数据共享，且边界条件颇具挑战性。这使得卷积成为复杂分块方法和输入数据暂存方法的重要应用场景，这些正是本章的重点。

7.1 背景

卷积是一种数组运算，其中每个输出数据元素是对应的输入元素与以它为中心的一组输入元素的加权和。加权和计算中所用的权重由滤波器数组定义，该数组通常被称为卷积核（convolution kernel）。由于 CUDA 核函数与卷积核（convolution kernel）之间存在令人遗憾的名称冲突，为了避免混淆，我们将这些滤波器数组称为卷积滤波器。

卷积可以对不同维度的输入数据执行：一维（1D）（如音频）、二维（2D）（如照片）、三维（3D）（如视频）等等。在音频数字信号处理中，输入的 1D 数组元素是按时间采样的信号音量。也就是说，输入数据元素 xi 是音频信号音量的第 i 个采样。对 1D 数据执行的卷积（称为 1D 卷积）在数学上定义为这样一个函数：它以包含 n 个元素的输入数据数组 [x0, x1, …, xn−1] 和包含 2r+ 1 个元素的滤波器数组 [f0, f1, …, f2r] 为输入，并返回输出数据数组 y：

yi=∑j=−rrfi+j×xi

由于滤波器的大小是奇数（2r+1)，因此加权和计算围绕被计算的元素对称。也就是说，加权和涉及被计算位置每一侧的r个输入元素，这正是r被称为滤波器半径的原因。

图 7.1 展示了一个 1D 卷积示例，其中将一个五元素（r= 2）的卷积滤波器 f 应用于一个七元素的输入数组 x。我们将遵循 C 语言的约定：x 和 y 元素的下标从 0 到 6，f 元素的下标从 0 到 4。由于滤波器半径为 2，每个输出元素都按对应输入元素、其左侧两个元素和右侧两个元素的加权和来计算。

例如，y[2] 的值由 x[0]（即 x[2 − 2]）到 x[4]（即 x[2 + 2]）的加权和生成。在本例中，我们任意假定 x 元素的值依次为 [8, 2, 5, 4, 1, 7, 3]。f 元素定义权重，本例中其值为 1, 3, 5, 3, 1。每个 f 元素先与对应的 x 元素值相乘，再把所有乘积相加。如图 7.1 所示，y[2] 的计算如下：

y[2]=f[0]*x[0]+f[1]*x[1]+f[2]*x[2]+f[3]*x[3]+f[4]*x[4]=1*8+3*2+5*5+3*4+1*1=52

在图 7.1 中，y[i] 的计算可以看作从 x[I − 2] 开始的 x 子数组与 f 数组之间的内积。图 7.2 展示了 y[3] 的计算。该计算相对图 7.1 中的计算沿 x 元素平移了一个位置。也就是说，y[3] 的值是 x[1]（即 x[3 − 2]）到 x[5]（即 x[3 + 2]）的加权和。我们可以把 x[3] 的计算看作如下内积：

y[3]=f[0]*x[1]+f[1]*x[2]+f[2]*x[3]+f[3]*x[4]+f[4]*x[5]y[3]=f[0]*x[1]+f[1]*x[2]+f[2]*x[3]+f[3]*x[4]+f[4]*x[5]=1*2+3*5+5*4+3*1+1*7=47

由于卷积是根据相邻元素来定义的，因此在计算靠近数组两端的输出元素时，自然会遇到边界条件。如图 7.3 所示，当计算 y[1] 时，x[1] 的左侧只有一个 x 元素。也就是说，按照我们对卷积的定义，没有足够的 x 元素来计算 y[1]。处理此类边界条件的一种典型做法是为这些缺失的 x 元素指定一个默认值。大多数应用把这个默认值取为 0，图 7.3 中我们使用的正是 0。例如，在音频信号处理中，我们可以假定录音开始之前和结束之后的信号音量都是 0。在这种情况下，y[1] 的计算如下：

y[1]=f[0]*0+f[1]*x[0]+f[2]*x[1]+f[3]*x[2]+f[4]*x[3]=1*0+3*8+5*2+3*5+1*4=53

该计算中不存在的 x 元素在图 7.3 中用虚线框表示。显然，y[0] 的计算会涉及两个缺失的 x 元素，本例中将它们都假定为 0。我们把 y[0] 的计算留作练习。这些缺失的元素在文献中通常被称为幽灵单元。由于并行计算中使用了分块，还存在其他类型的幽灵单元。这些幽灵单元会对分块的效果和/或效率产生显著影响。我们很快就会回到这一点。

此外，并非所有应用都假定幽灵单元的值为 0。例如，有些应用可能假定幽灵单元的值与边缘上最近的有效数据元素相同。

对于图像处理和计算机视觉，输入数据通常表示为二维数组，像素位于 x–y 空间中。因此图像卷积是 2D 卷积，如图 7.4 所示。在 2D 卷积中，滤波器 f 也是一个 2D 数组。它的 x 和 y 维度决定了加权和计算中要包含的邻居范围。如果我们假定滤波器在 x 维度上的尺寸为（2rx+ 1），在 y 维度上的尺寸为（2ry+ 1），那么每个 P 元素的计算可以表示如下：

7.3 常量内存与缓存

滤波器数组 F 在卷积中的使用方式有三个有趣的特性。首先，F 的尺寸通常很小；大多数卷积滤波器的半径为 7 或更小。即使在 3D 卷积中，滤波器通常也只包含不超过 73= 343 个元素。其次，在整个卷积核函数的执行过程中，F 的内容不会改变。第三，所有线程都会访问滤波器元素。更好的是，所有线程都按相同的顺序访问 F 元素：从 F[0][0]开始，在图 7.7 中双重嵌套 for 循环的每次迭代中一次移动一个元素。这三个特性使滤波器成为使用常量内存和缓存（图 7.8）的绝佳候选。

正如我们在第 5 章《内存体系结构与数据局部性》（表 5.1）中讨论过的，CUDA C 允许程序员声明驻留在常量内存中的变量。与全局内存变量一样，常量内存变量对所有线程块可见。主要区别在于，常量内存变量的值在核函数执行期间不能被线程修改。此外，常量内存的容量相当小，目前为 64 KB。

与全局内存变量一样，常量内存变量也位于 DRAM 中。然而，由于 CUDA 运行时知道常量内存变量在核函数执行期间不会被修改，它会指示硬件在核函数执行期间积极缓存这些常量内存变量。要理解使用常量内存的好处，我们需要先更深入地了解现代处理器的内存和缓存层次结构。

正如我们在第 6 章《性能考量》中讨论过的，DRAM 的长延迟和有限带宽在几乎所有现代处理器中都构成瓶颈。为了减轻这一内存瓶颈的影响，现代处理器通常采用片上缓存存储器（简称缓存），以减少需要从主存（DRAM）访问的变量数量，如图 7.10 所示。

与 CUDA 共享内存（更一般地说是便笺存储器）不同，缓存对程序是“透明”的。也就是说，要使用 CUDA 共享内存来保存全局变量的值，程序需要把变量声明为__shared__，并显式地把全局内存变量的值拷贝到共享内存变量中。而使用缓存时，程序只需访问原来的全局内存变量。处理器硬件会自动在缓存中保留最近或经常使用的变量，并记住它们原来的全局内存地址。当之后用到某个被保留的变量时，硬件会从其地址判断出缓存中已有该变量的副本，然后直接从缓存提供该变量的值，从而无需访问 DRAM。

内存的容量与速度之间存在权衡。因此，现代处理器通常采用多级缓存。这些缓存级别的编号约定反映了它们到处理器的距离。最低一级的 L1（第 1 级）缓存直接挂在处理器核心上，如图 7.10 所示，其延迟和带宽都接近处理器本身的速度。然而，L1 缓存的容量很小，通常为 16 至 64 KB。L2 缓存更大，容量从几百 KB 到几 MB，但访问可能需要几十个时钟周期。它们通常在多个处理器核心（即 CUDA 设备中的流式多处理器（SM））之间共享，因此访问带宽也是各 SM 共享的。在当今一些高端处理器中，甚至还有容量可达数百 MB 的 L3 缓存。

常量内存变量在大规模并行处理器的内存设计与使用中扮演着一个有趣的角色。由于这些常量内存变量在核函数执行期间不会被修改，因此在 SM 中缓存它们时，无需支持线程写入。支持向通用缓存进行高吞吐量写入需要复杂的硬件逻辑，在芯片面积和功耗方面代价高昂。由于无需支持写入，可以针对常量内存变量设计专用缓存，使它在芯片面积和功耗方面都非常高效。此外，由于常量内存相当小（64 KB），一个小型的专用缓存就能非常有效地容纳每个核函数大量使用的常量内存变量。这种专用缓存在现代 GPU 中被称为常量缓存。因此，当一个线程束中的所有线程访问同一个常量内存变量时——如图 7.9 中 F 的情形，其中访问 F 的索引与线程索引无关——常量缓存可以提供巨大的带宽来满足这些线程的数据需求。另外，由于 F 的尺寸通常很小，我们可以假定所有 F 元素实际上总是从常量缓存中访问。因此，我们可以简单假定没有 DRAM 带宽花费在访问 F 元素上。通过使用常量内存和缓存，我们实际上把浮点算术与内存访问之比提高了一倍，达到约 0.5 OP/B（第 10 行每加载 4 字节执行 2 次运算）。

事实证明，对输入 N 数组元素的访问也能从缓存中受益。我们将在第 7.5 节回到这一点。

7.4 带光环单元的分块卷积

我们可以用分块卷积算法来解决卷积的内存带宽瓶颈。回顾一下，在分块算法中，线程协作把输入元素加载到片上内存中，供后续使用。我们首先确立输入分块和输出分块的定义，因为这些定义对理解算法的设计很重要。我们把每个线程块处理的输出元素集合称为一个输出分块。回顾图 7.6，它展示了一个 16 × 16 的 2D 卷积小型示例，使用 16 个线程块，每块 16 个线程。在那个示例中一共有 16 个输出分块。请记住，我们使用每块 16 个线程只是为了把示例做小。在实践中，每个线程块至少应有 32 个线程（即一个线程束），通常还要多得多，以获得良好的占用率和数据重用。从现在开始，我们将假定 F 元素位于常量内存中。

我们将输入分块定义为计算一个输出分块中的 P 元素所需的输入 N 元素的集合。图 7.11 展示了与一个输出分块（右侧阴影区域）对应的输入分块（左侧阴影区域）。请注意，输入分块的尺寸需要在每个方向上都向外扩展滤波器半径（本例中为 2），以确保它包含计算输出分块边缘处 P 元素所需的全部光环输入元素。这种扩展会使输入分块明显大于输出分块。在这个小型示例中，每个输出分块包含 42= 16 个 P 元素，而每个输入分块包含（4 + 4）2= 82= 64 个元素。在这种情况下，输入分块比输出分块大 4 倍。不过，这个较大的比值是因为我们在小型示例中为便于可视化而假定了极小的输出分块尺寸。在实践中，输出分块的尺寸会大得多，输入分块大小与输出分块大小之比会更接近 1.0。例如，如果输出尺寸为 16 × 16 = 256，在同样的 5 × 5 滤波器下，输入分块大小将为（16 + 4）2= 400，输入分块大小与输出尺寸之比约为 1.6。虽然这个比值远小于 4，但它表明，即使对于实际规模的输出分块尺寸，输入分块仍然可能明显大于输出分块。

本节介绍一类分块卷积算法：线程块中的全部线程首先协作把输入分块加载到共享内存中，然后再通过访问共享内存中的输入元素来计算输出分块的元素。读者应该对此感到熟悉；这一策略与第 5 章《内存体系结构与数据局部性》中讨论的分块矩阵乘法算法类似。主要区别在于，第 5 章《内存体系结构与数据局部性》中的分块矩阵乘法算法假定输入分块与输出分块的维度相同，而卷积的输入分块大于输出分块。输入分块大小与输出分块大小之间的这种差异使分块卷积核函数的设计变得复杂。

针对输入分块大小与输出分块大小之间的差异，有两种简单的线程组织方式。第一种是启动维度与输入分块匹配的线程块。这简化了输入分块的加载，因为每个线程只需加载一个输入元素。然而，由于线程块维度大于输出分块，在计算输出元素时需要停用部分线程，这可能会降低执行资源利用的效率。第二种是启动维度与输出分块匹配的线程块。一方面，这种策略使输入分块的加载更复杂，因为线程需要迭代多次，以确保所有输入分块元素都被加载。另一方面，它简化了输出元素的计算，因为线程块维度与输出分块相同，在计算输出元素期间无需停用任何线程。我们将给出基于第一种线程组织方式的核函数设计，并把第二种组织方式留作练习。

图 7.12 展示了基于第一种线程组织方式的核函数。每个线程首先计算它负责加载或计算的输入或输出元素的列索引（col）和行索引（row）（第 06–07 行）。该核函数分配一个大小与输入分块相同的共享内存数组 N_s（第 09 行），并把输入分块加载到该共享内存数组中（第 10–15 行）。第 10 行的条件用于让每个线程检查它试图加载的输入分块元素是否为幽灵单元。如果是，该线程不执行内存加载，而是在共享内存中放入一个零。所有线程执行一次屏障同步（第 15 行），以确保整个输入分块都已就位到共享内存中，之后任何线程才可以继续计算输出元素。

现在所有输入分块元素都已放入 N_ds 数组中，每个线程都可以利用 N_ds 元素计算其输出 P 元素的值。请记住，输出分块小于输入分块，而且线程块与输入分块大小相同，因此每个线程块中只有一部分线程会用于计算输出分块元素。选择哪些线程来计算有多种方式。我们采用的设计会停用 FILTER_RADIUS 圈外层线程，如图 7.13 所示。

图 7.13 展示了一个小型的卷积示例，使用 3 × 3 的滤波器（FILTER_RADIUS=1）、8 × 8 的输入分块、8 × 8 的线程块和 6 × 6 的输出分块。图 7.13 的左侧展示了输入分块和线程块。由于它们大小相同，二者重叠在一起。按照我们的设计，停用 FILTER_RADIUS=1 圈外层线程。图 7.13 左侧中央的粗线框圈出了用于计算输出分块元素的活跃线程。在本例中，活跃线程的 threadIdx.x 和 threadIdx.y 值都从 1 到 6。

图 7.13 还展示了活跃线程到输出分块元素的映射：活跃线程（tx, ty）将利用一块输入分块元素来计算输出元素（tx - FILTER_RADIUS, ty - FILTER_RADIUS），该输入分块元素块的左上角是输入分块的元素（tx - FILTER_RADIUS, ty - FILTER_RADIUS）。这体现在图 7.12 的第 17–18 行，其中列索引(tileCol)和行索引(tileRow)分别被赋值为 threadIdx.x-FILTER_RADIUS 和 threadId.y-FILTER_RADIUS。

在图 7.13 的小示例中，线程 (1,1) 的 tileCol 和 tileRow 分别为 0 和 0。因此线程 (1, 1) 使用输入分块左上角虚线框标出的 3 × 3 输入分块元素块，计算输出分块的元素 (0,0)。图 7.12 第 24–28 行的 fRow-fCol 循环嵌套遍历该元素块并生成输出元素。线程块中的线程 (1,1) 将遍历左上角为 N_s[0][0]的元素块，而线程 (5,5) 将遍历左上角为 N_s[5][5]的元素块。

在第 06–07 行中，blockIdx.x*OUT_TILE_DIM 和 blockIdx.y*OUT_TILE_DIM 分别是分配给该线程块的输出分块起点的水平与垂直 P 数组索引。正如我们之前讨论过的，threadIdx.x-r 和 threadIdx.y-r 给出分块内的偏移量。这样，row 和 col 变量就提供了分配给每个活跃线程的输出元素索引。每个线程在第 29 行用这两个索引写入输出元素的最终值。

图 7.12 中的分块 2D 卷积核函数比图 7.9 中的基础核函数要长得多，也复杂得多。我们引入这些额外的复杂度是为了减少访问 N 元素所需的 DRAM 访问次数。其目标是提高算术运算与全局内存访问之比，使实际性能不受或较少受 DRAM 带宽的限制。回顾第 7.4 节，图 7.9 中核函数的算术运算与全局内存访问之比为 0.5 OP/B。现在让我们为图 7.12 中的核函数推导这一比值。

对于处理数据边缘分块的线程块，处理幽灵单元的线程不会为这些幽灵单元执行任何内存访问，从而减少了这些线程块的内存访问次数。我们可以通过枚举使用每个幽灵单元的线程数来计算减少后的内存访问次数。不过，显然对于大型输入数组，当掩码很小时，幽灵单元的影响可以忽略不计。因此，在计算分块卷积核函数的算术运算与全局内存访问之比时，我们将忽略幽灵单元的影响，只考虑光环单元不是幽灵单元的内部线程块。

现在我们来计算图 7.12 中分块核函数的算术运算与全局内存访问之比。分配给输出分块元素的每个线程，对滤波器的每个元素都要执行一次乘法和一次加法。因此，内部线程块中的线程共执行 OUT_TILE_DIM2*(2*FILTER_RADIUS + 1)2*2 次算术运算。至于全局内存访问，所有的全局内存访问都已转移到把 N 元素加载到共享内存的代码中。分配给输入分块元素的每个线程加载一个 4 字节的输入值。因此，每个内部线程块加载 IN_TILE_DIM2*4=(OUT_TILE_DIM+2*FILTER_RADIUS)2*4 字节。因此，该分块核函数的算术运算与全局内存访问之比为

OUT_TILE_DIM2*(2*FILTER_RADIUS+1)2*2(OUT_TILE_DIM+2*FILTER_RADIUS)2*4

以我们的示例为例，5 × 5 的滤波器和 32 × 32 的输入分块（28 × 28 的输出分块），该比值为282×52*2322*4=9.57OP/B。32 × 32 的输入分块大小是当前 GPU 上可达到的最大尺寸。不过，我们可以对分块大小做渐近分析，以得到该计算可达的算术运算与全局内存访问之比的上界。如果 OUT_TILE_DIM 远大于 FILTER_RADIUS，我们可以认为 OUT_TILE_DIM+2*FILTER_RADIUS 约等于 OUT_TILE_DIM。这样表达式就简化为(2*FILTER_RADIUS+1)2*2/4。这应当是一个相当直观的结果。在原始算法中，每个 N 元素会被大约(2*FILTER_RADIUS+1)2 个线程重复加载，每个线程对它执行两次算术运算。因此，如果分块大小无限大，且每个 4 字节元素只被加载到共享内存一次，该比值应为(2*FILTER_RADIUS+1)2*2/4。

图 7.14 展示了不同滤波器大小下分块卷积核函数的算术运算与全局内存访问之比如何随分块维度变化，其中还给出了渐近上界。5 × 5 滤波器的比值上界为 12.5 OP/B。然而，在 32 × 32 的线程块大小限制下，实际可达到的比值为 9.57 OP/B。对于更大的滤波器，如图 7.14 最下面一行的 9 × 9，比值的上界为 40.5 OP/B，而在 32 × 32 的线程块大小限制下，实际可达到的比值为 22.78 OP/B。因此我们观察到，滤波器越大，比值越高，因为每个输入元素会被更多的线程使用。不过，滤波器越大，上界与实际达到的比值之间的差距也越大，因为光环元素越多，迫使输出分块越小。

读者在使用小块和小分块时应始终保持谨慎。它们可能使内存访问次数的减少量远低于预期。例如，在图 7.14 中，7.8× 8 的线程块（输入分块）对 5 × 5 的滤波器只能得到 3.13 OP/B 的比值。在实践中，由于片上内存不足，常常使用较小的分块大小，尤其是在 3D 卷积中，所需的片上内存量会随分块维度的增大而迅速增长。

7.5 利用缓存处理光环单元的分块卷积

在图 7.12 中，代码的大部分复杂性源于这样一个事实：由于要加载光环单元，输入分块和线程块都大于输出分块。回顾一下，一个线程块输入分块的光环单元同时也是相邻分块的内部元素。例如，在图 7.11 中，某个输入分块的浅色光环单元也是相邻线程块输入分块的内部元素。当一个线程块需要其光环单元时，有很大概率它们已经在 L2 缓存中，因为相邻线程块的访问已经把它们带了进来。因此，对这些光环单元的内存访问可能会自然地从 L2 缓存得到满足，而不会产生额外的 DRAM 流量。也就是说，我们可以让对这些光环单元的访问保持对原始 N 元素的访问，而不必把它们加载到 N_ds 中。现在，我们给出一种分块卷积算法，它让输入分块和输出分块采用相同的维度，并且只把每个分块的内部元素加载到共享内存中。

图 7.15 展示了一个利用缓存处理光环单元的 2D 卷积核函数。在这个分块核函数中，共享内存数组 N_ds 只需要容纳分块的内部元素。这样，输入分块和输出分块具有相同的维度，该维度被定义为常量 TILE_DIM（第 1 行）。有了这个简化，N_s 被声明为在 x 和 y 两个维度上各有 TILE_DIM 个元素（第 6 行）。

由于输入分块和输出分块大小相同，线程块可以按与它们相同的大小来启动。加载 N_s 元素变得更简单，因为每个线程只需加载与其负责的输出元素具有相同 x、y 坐标的输入元素（第 4–5 行和第 7–11 行）。第 7 行中加载输入元素的条件也得以简化：由于核函数不再把光环单元加载到共享内存中，也就不存在加载幽灵单元的危险。因此，该条件只需检查通常的边界条件，即分块可能超出输入数据的有效范围。

不过，计算 P 元素的循环体变得更复杂了。它需要增加条件来检查光环单元和幽灵单元的使用。光环单元的处理由第 17–20 行的条件完成，这些条件检查输入元素是否位于输入分块的内部。如果是，则从共享内存访问该元素；如果不是，第 24–27 行的条件检查这些光环单元是否为幽灵单元。如果是，则对该元素不做任何操作，因为我们假定幽灵值为 0；否则，从全局内存访问该元素。读者可以自行验证，处理幽灵单元的条件与图 7.7 中所用的条件类似。

与图 7.12 中的核函数相比，图 7.15 中核函数的一个微妙优势是，其线程块大小、输入分块大小和输出分块大小可以相同，而且可以是 2 的幂。由于图 7.12 中核函数的输入分块大小与输出分块大小不同，该核函数在执行期间很可能出现更多的内存发散和控制发散。

7.6 小结

在本章中，我们研究了卷积这一重要的并行计算模式。虽然卷积被用于计算机视觉和视频处理等许多应用中，但它也代表了一种通用模式，构成许多并行算法的基础。例如，可以把偏微分方程求解器中的模板算法视为卷积的特例，这将是第 8 章《模板》的主题。再如，也可以把网格点作用力或势能值的计算视为卷积的特例，这将在第 17 章《迭代式磁共振成像重建》中介绍。我们还将在第 16 章《深度学习》中运用本章学到的许多知识来研究卷积神经网络。

我们给出了一种基础并行卷积算法，其实现将受限于访问输入元素和滤波器元素所需的 DRAM 带宽。随后我们介绍了常量内存，以及对核函数和主机代码做的一个简单修改，以利用常量缓存并几乎完全消除访问滤波器元素所需的 DRAM 访问。我们还进一步介绍了一种分块并行卷积算法，它通过利用共享内存来降低 DRAM 带宽消耗，同时引入了更多的控制流发散和编程复杂性。最后，我们给出了一种分块并行卷积算法，它利用 L1 和 L2 缓存来处理光环单元。

我们从提高算术运算与全局内存访问之比的角度，对分块的收益进行了分析。这种分析是一项重要技能，有助于理解分块对其他模式的收益。通过该分析，我们可以了解到小分块大小的局限性，这种局限性在大滤波器和 3D 卷积中尤为明显。

虽然我们只给出了 1D 和 2D 卷积的核函数示例，但这些技术同样直接适用于 3D 卷积。一般来说，由于维数更高，输入和输出数组的索引计算会更复杂。此外，每个线程会有更多层的循环嵌套，因为在加载分块和/或计算输出值时需要遍历多个维度。我们鼓励读者把这些高维核函数作为家庭作业来完成。
