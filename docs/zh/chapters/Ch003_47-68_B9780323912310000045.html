3.1 多维网格组织

在 CUDA 中，网格内的所有线程执行同一个核函数，它们依靠坐标（即线程索引）彼此区分，并确定各自应处理的数据部分。正如我们在第 2 章“异构数据并行计算”中所见，这些线程被组织成两级层次结构：一个网格由一个或多个线程块组成，每个线程块由一个或多个线程组成。同一线程块中的所有线程共享相同的线程块索引，该索引可通过 blockIdx（内置）变量访问。每个线程还有一个线程索引，可通过 threadIdx（内置）变量访问。当线程执行核函数时，对 blockIdx 和 threadIdx 变量的引用返回该线程的坐标。核函数调用语句中的执行配置参数指定网格的维度以及每个线程块的维度。这些维度可通过 gridDim 和 blockDim（内置）变量获得。

一般来说，网格是线程块的三维（3D）数组，而每个线程块是线程的 3D 数组。调用核函数时，程序需要指定网格和线程块在每一维上的大小。它们通过核函数调用语句的执行配置参数（位于<<<…>>>之内）来指定。第一个执行配置参数以线程块的数目指定网格的维度，第二个以线程的数目指定每个线程块的维度。每个这样的参数都具有 dim3 类型，它是由 x、y、z 三个元素构成的整型向量类型。这三个元素指定三个维度的大小。程序员可以把未使用维度的大小设为 1，从而使用少于三个的维度。

在 CUDA C 中，gridDim.x 的允许取值为 1 至 231 − 1，1 而 gridDim.y 和 gridDim.z 的允许取值为 1 至 216 − 1（65,535）。线程块中的所有线程共享相同的 blockIdx.x、blockIdx.y 和 blockIdx.z 值。在各线程块之间，blockIdx.x 的取值范围为 0 至 gridDim.x-1，blockIdx.y 的取值范围为 0 至 gridDim.y-1，blockIdx.z 的取值范围为 0 至 gridDim.z-1。

现在把注意力转向线程块的配置。每个线程块被组织成线程的 3D 数组。把 blockDim.z 设为 1 即可创建二维（2D）线程块；把 blockDim.y 和 blockDim.z 都设为 1 即可创建一维线程块，正如 vectorAddkernel 例子中那样。如前所述，一个网格中的所有线程块具有相同的维度和大小。线程块每一维上的线程数由核函数调用时的第二个执行配置参数指定。在核函数内部，该配置参数可通过 blockDim 的 x、y、z 字段访问。

在当前的 CUDA 系统中，一个线程块的总大小上限为 1024 个线程。只要线程总数不超过 1024，这些线程可以按任意方式分布到三个维度上。例如，blockDim 取值为 (512, 1, 1)、(8, 16, 4) 和 (32, 16, 2) 都是允许的，但 (32, 32, 2) 不被允许，因为线程总数会超过 1024。

3.2 将线程映射到多维数据

选择 1D、2D 还是 3D 的线程组织，通常取决于数据本身的性质。例如，图片是像素的 2D 数组。用由 2D 线程块构成的 2D 网格来处理图片中的像素往往很方便。图 3.2 展示了处理一幅 62×762 图片 P 的这样一种安排（垂直方向或 y 方向 62 个像素，水平方向或 x 方向 76 个像素）。假设我们决定采用 16×16 的线程块，x 方向 16 个线程，y 方向 16 个线程。那么 y 方向需要 4 个线程块，x 方向需要 5 个线程块，共得到 4×5=20 个线程块，如图 3.2 所示。粗线标出线程块的边界。阴影区域表示覆盖像素的线程。每个线程被指派处理一个像素，该像素的 y 坐标和 x 坐标由此线程的 blockIdx、blockDim 和 threadIdx 变量的值导出：

Vertical(row)rowcoordinate=blockIdx.y*blockDim.y+threadIdx.y

Horizontal(Column)coordinate=blockIdx.x*blockDim.x+threadIdx.x

例如，由线程块 (1,0) 的线程 (0,0) 处理的 Pin 元素可按如下方式确定：

PinblockIdx.y*blockDim.y+threadIdx.y,blockIdx.x*blockDim.x+threadIdx.x=Pin1*16+0,0*16+0=Pin16,0

在给出核函数代码之前，先要理解 C 语句如何访问动态分配的多维数组的元素。理想情况下，我们希望把 Pin_d 当作 2D 数组来访问，用 Pin_d[j][i]访问第 j 行第 i 列的元素。然而，CUDA C 所依据的 ANSI C 标准要求：只有在编译时已知 Pin 的列数，才能把 Pin 当作 2D 数组来访问。遗憾的是，对动态分配的数组而言，这一信息在编译时是未知的。事实上，使用动态分配数组的部分原因，正是要让这些数组的大小和维度在运行时随数据规模变化。因此，动态分配的 2D 数组的列数信息，在设计上就注定无法在编译时得知。于是，在当前的 CUDA C 中，程序员需要显式地把动态分配的 2D 数组线性化（或者说“压平”）为一个等价的 1D 数组。

实际上，C 语言中所有的多维数组都会被线性化。这是因为现代计算机采用“平坦”的内存空间（参见“内存空间”专栏）。对于静态分配的数组，编译器允许程序员使用高维索引语法（例如 Pin_d[j][i]）来访问其元素。在底层，编译器把它们线性化为等价的 1D 数组，并把多维索引语法翻译成 1D 偏移量。而对于动态分配的数组，由于编译时缺少维度信息，当前的 CUDA C 编译器把这一翻译工作留给了程序员。

内存空间

内存空间是对现代计算机中处理器如何访问其内存的一种简化视图。通常，每个正在运行的应用程序都关联着一个内存空间。应用程序要处理的数据以及为该程序执行的指令，都存放在其内存空间中的各个位置上。每个位置通常可容纳一个字节，并有一个地址。需要多个字节的变量——float 占 4 字节，double 占 8 字节——存放在连续的字节位置上。当从内存空间访问一个数据值时，处理器给出起始地址（起始字节位置的地址）和所需的字节数。

大多数现代计算机至少拥有 4G 个字节大小的位置，其中每个 G 是 1,073,741,824（230）。所有位置都用地址标记，地址范围从 0 到所用到的最大数。由于每个位置只有一个地址，我们说内存空间具有“平坦”的组织形式。因此，所有多维数组最终都会被“压平”为等价的一维数组。虽然 C 程序员可以用多维数组语法访问多维数组的元素，但编译器会把这些访问翻译成一个指向数组首元素的基指针，加上由这些多维索引计算出的一维偏移量。

把 2D 数组线性化至少有两种方式。一种是把同一行的所有元素放在连续的位置上，然后把各行一行接一行地放入内存空间。这种排列称为行主序布局，如图 3.3 所示。为提高可读性，我们用 Mj,i 表示 M 中第 j 行第 i 列的元素。Mj,i 等价于 C 表达式 M[j][i]，但略微更易读。图 3.3 给出一个例子：一个 4×4 的矩阵 M 被线性化为 16 个元素的 1D 数组，先是第 0 行的全部元素，接着是第 1 行的四个元素，依此类推。因此，M 中第 j 行第 i 列元素的 1D 等价索引为 j*4+i。其中 j*4 一项跳过第 j 行之前各行的所有元素，i 一项再在第 j 行的区段内选出正确的元素。例如，M2,1 的 1D 索引为 2*4+1=9。这一点在图 3.3 中有所展示：其中 M9 就是 M2,1 的 1D 等价形式。C 编译器正是以这种方式线性化 2D 数组的。

把 2D 数组线性化的另一种方式，是把同一列的所有元素放在连续的位置上，然后把各列一列接一列地放入内存空间。这种排列称为列主序布局，FORTRAN 编译器采用的就是它。注意，2D 数组的列主序布局等价于其转置形式的行主序布局。这里不再多花篇幅，只提醒一点：此前主要使用 FORTRAN 编程的读者应当注意，CUDA C 使用的是行主序布局而非列主序布局。此外，许多供 FORTRAN 程序使用的 C 库为与 FORTRAN 编译器的布局保持一致，也采用列主序布局。因此，这些库的手册通常会告诉用户：若从 C 程序中调用它们，需要先把输入数组转置。

第一块区域在图 3.5 中标为 1，由覆盖图片大部分像素的 12 个线程块中的线程组成。这些线程的 col 值和 row 值都在范围内；它们全都通过 if 语句的检验，处理图片中深色阴影区域的像素。也就是说，每个线程块中全部 16×16=256 个线程都会处理像素。

第二块区域在图 3.5 中标为 2，包含中等阴影区域内三个线程块中的线程，它们覆盖图片右上部的像素。虽然这些线程的 row 值总在范围内，但其中一些线程的 col 值超过了 m 的取值 76。这是因为水平方向的线程数总是程序员所选 blockDim.x 值（这里是 16）的整数倍，而覆盖 76 个像素所需的 16 的最小倍数是 80。结果，每行中有 12 个线程的 col 值落在范围内，会处理像素；每行余下的 4 个线程的 col 值超出范围，因而不满足 if 语句的条件，不会处理任何像素。总体来看，这些线程块中每块 16×16=256 个线程里有 12×16=192 个会处理像素。

第三块区域在图 3.5 中标为 3，对应覆盖图片中等阴影区域的左下方四个线程块。虽然这些线程的 col 值总在范围内，但其中一些线程的 row 值超过了 n 的取值 62。这是因为垂直方向的线程数总是程序员所选 blockDim.y 值（这里是 16）的整数倍，而覆盖 62 所需的 16 的最小倍数是 64。结果，每列中有 14 个线程的 row 值落在范围内，会处理像素；每列余下的 2 个线程无法通过 if 语句，不会处理任何像素。总体来看，256 个线程中有 16×14=224 个会处理像素。

第四块区域在图 3.5 中标为 4，包含覆盖图片右下方浅色阴影区域的线程。与区域 2 类似，最上面 14 行中每行有 4 个线程的 col 值超出范围；与区域 3 类似，该线程块最下面整整两行的 row 值超出范围。总体来看，16×16=256 个线程中只有 14×12=168 个会处理像素。

只要在线性化数组时再加入一个维度，就可以很容易地把对 2D 数组的讨论推广到 3D 数组。做法是把数组的每个“平面”一个接一个地放入地址空间。假设程序员用变量 m 和 n 分别记录 3D 数组的列数和行数，调用核函数时还需要确定 blockDim.z 和 gridDim.z 的取值。在核函数中，数组索引将涉及另一个全局索引：

3.3 图像模糊：一个更复杂的核函数

我们已经研究了 vecAddkernel 和 colorToGrayscaleConversion，其中每个线程只对一个数组元素执行少量算术运算。这些核函数很好地达成了各自的目的：说明 CUDA C 程序的基本结构以及数据并行执行的概念。读到这里，读者自然会提出一个显而易见的问题：CUDA C 程序中的所有线程都只是彼此独立地执行这样简单而平凡的运算吗？答案是否定的。在真实的 CUDA C 程序中，线程往往要对其数据执行复杂的运算，并且需要彼此协作。接下来的几章将处理越来越复杂、体现这些特点的例子。我们先从一个图像模糊函数开始。

图像模糊在平滑像素值突变的同时，保留对识别图像关键特征至关重要的边缘。图 3.6 展示了图像模糊的效果。简单地说，就是把图像变模糊。在人眼看来，模糊后的图像往往会淡化细节，呈现出“大局”印象，也就是图片中的主要主题对象。在计算机图像处理算法中，图像模糊的一个常见用途是用周围干净的像素值修正有问题的像素值，从而降低图像中噪声和颗粒状渲染效果的影响。在计算机视觉中，图像模糊可以让边缘检测和目标识别算法聚焦于主题对象，而不至于被海量的细粒度对象所拖累。在显示方面，有时会通过模糊图像的其余部分来突出图像中的某一特定区域。

从数学上说，图像模糊函数把输出图像中某个像素的值，计算为输入图像中包含该像素在内的一片像素块的加权和。正如我们将在第 7 章“卷积”中学到的，这类加权和的计算属于卷积模式。本章采用一种简化的做法：对围绕目标像素（并包含该像素）的 N×N 像素块取简单平均值。为使算法保持简单，我们不会依据像素与目标像素的距离为其取值分配权重。实际上，在诸如高斯模糊之类的卷积模糊方法中，施加这样的权重是相当常见的。

图 3.7 给出了使用 3×3 像素块进行图像模糊的例子。在计算 (row, col) 位置上的输出像素值时，可以看到该像素块以位于 (row, col) 位置的输入像素为中心。这个 3×3 像素块横跨三行（row-1、row、row+1）和三列（col-1、col、col+1）。例如，计算 (25, 50) 处输出像素所用的九个像素，其坐标为 (24, 49)、(24, 50)、(24, 51)、(25, 49)、(25, 50)、(25, 51)、(26, 49)、(26, 50) 和 (26, 51)。

图 3.8 给出了一个图像模糊核函数。与 colorToGrayscaleConversion 所用的策略类似，我们让每个线程计算一个输出像素，也就是说，线程到输出数据的映射保持不变。因此在核函数开头可以看到熟悉的 col 和 row 索引计算（第 03–04 行），也可以看到熟悉的 if 语句，它按图像的高度和宽度验证 col 和 row 是否都在有效范围内（第 05 行）。只有 col 和 row 索引都落在取值范围内的线程才被允许参与执行。

如图 3.7 所示，col 和 row 的值同时也给出了用于计算该线程输出像素的那片输入像素块的中心像素位置。图 3.8 中的嵌套 for 循环（第 10–11 行）遍历像素块中的所有像素。我们假设程序中定义了常量 BLUR_SIZE。BLUR_SIZE 的取值按如下方式设定：BLUR_SIZE 给出像素块每一侧的像素数（半径），而 2*BLUR_SIZE+1 给出像素块在一个维度上的像素总数。例如，对 3×3 的像素块，BLUR_SIZE 设为 1；而对 7×7 的像素块，BLUR_SIZE 设为 3。外层循环遍历像素块的各行；对每一行，内层循环遍历像素块的各列。

在 3×3 像素块的例子中，BLUR_SIZE 为 1。对于计算输出像素 (25, 50) 的线程，在外层循环的第一次迭代中，curRow 变量为 row-BLUR_SIZE=(25−1)=24。因此在外层循环的第一次迭代中，内层循环遍历第 24 行的像素块像素。内层循环借助 curCol 变量，从列 col-BLUR_SIZE=50–1=49 迭代到 col+BLUR_SIZE=51。所以外层循环第一次迭代中处理的像素是 (24, 49)、(24, 50) 和 (24, 51)。读者应自行验证：在外层循环的第二次迭代中，内层循环遍历像素 (25, 49)、(25, 50) 和 (25, 51)；最后，在外层循环的第三次迭代中，内层循环遍历像素 (26, 49)、(26, 50) 和 (26, 51)。

第 16 行利用 curRow 和 curCol 的线性化索引，访问本次迭代所访问的输入像素的值，并把该像素值累加到累加和变量 pixVal 中。第 17 行通过递增 pixels 变量，记录下又有一个像素值被加入累加和这一事实。像素块中的所有像素处理完毕后，第 22 行用 pixVal 的值除以 pixels 的值，算出像素块中各像素的平均值，并利用 row 和 col 的线性化索引把结果写入其输出像素。

第 15 行包含一条条件语句，用于守护第 16 行和第 17 行的执行。例如，在计算靠近图像边缘的输出像素时，像素块可能会超出输入图像的有效范围。图 3.9 以 3×3 像素块为例说明了这种情形。在情形 1 中，正在被模糊的是左上角的像素，预期像素块中的九个像素有五个在输入图像中并不存在。此时输出像素的 row 值和 col 值分别为 0 和 0。在嵌套循环执行期间，九次迭代的 curRow 和 curCol 取值依次为 (−1,−1)、(−1,0)、(−1,1)、(0,−1)、(0,0)、(0,1)、(1,−1)、(1,0) 和 (1,1)。注意，对图像之外的那五个像素，至少有一个取值小于 0。if 语句中的 curRow<0 和 curCol<0 条件会捕捉到这些取值，并跳过第 16 行和第 17 行的执行。结果，只有四个有效像素的值被累加到累加和变量中；pixels 的值也正确地只递增了四次，使第 22 行能正确算出平均值。

读者应逐一分析图 3.9 中的其他情形，并考察 blurKernel 中嵌套循环的执行行为。注意，大多数线程都能在输入图像内找到其所分配的 3×3 像素块中的全部像素，它们会累加全部九个像素。然而，对于四个角上的像素，负责的线程只会累加四个像素；对于四条边上的其他像素，负责的线程会累加六个像素。正是这些差异，才使得有必要用变量 pixels 记录实际累加的像素数目。

3.4 矩阵乘法

矩阵-矩阵乘法，简称矩阵乘法，是基本线性代数子程序（Basic Linear Algebra Subprograms，BLAS）标准的重要组成部分（参见“线性代数函数”补充栏）。它是许多线性代数求解器（如 LU 分解）的基础，也是使用卷积神经网络（CNN）进行深度学习时的一项重要计算，这将在第 16 章“深度学习”中详细讨论。

线性代数函数

线性代数运算在科学与工程应用中被广泛使用。基本线性代数子程序（BLAS）是发布基本代数运算库的事实标准，其中的线性代数函数分为三个层级。层级越高，函数所执行的运算数量越多。第 1 层函数执行形如 y=αx+y 的向量运算，其中 x 和 y 是向量，α 是标量。我们的向量加法例子就是 α=1 时第 1 层函数的一个特例。第 2 层函数执行形如 y=αAx+βy 的矩阵-向量运算，其中 A 是矩阵，x 和 y 是向量，α 和 β 是标量。我们将在稀疏线性代数中研究一种第 2 层函数。第 3 层函数执行形如 C=αAB+βC 的矩阵-矩阵运算，其中 A、B 和 C 是矩阵，α与 β 是标量。我们的矩阵-矩阵乘法例子就是 α=1 且 β=0 时第 3 层函数的一个特例。这些 BLAS 函数之所以重要，是因为它们被用作更高层代数函数（如线性方程组求解器和特征值分析）的基本构件。正如后面将要讨论的，BLAS 函数的不同实现，其性能在串行计算机和并行计算机上都可能相差若干个数量级。

一个 I×j（i 行 j 列）矩阵 M 与一个 j×k 矩阵 N 相乘，产生一个 I×k 矩阵 P。执行矩阵乘法时，输出矩阵 P 的每个元素都是 M 的某一行与 N 的某一列的内积。我们将继续沿用如下约定：Prow, col 表示垂直方向第 row 个位置、水平方向第 col 个位置上的元素。如图 3.10 所示，Prow,col（P 中的小方块）是由 M 的第 row 行构成的向量（在 M 中显示为一条水平条带）与由 N 的第 col 列构成的向量（在 N 中显示为一条垂直条带）的内积。两个向量的内积，有时也称为点积，是各向量元素乘积之和。即，

Prow,col=∑Mrow,k*Nk,colfork=0,1,…Width−1

例如，在图 3.10 中，假设 row=1 且 col=5，

P1,5=M1,0*N0,5+M1,1*N1,5+M1,2*N2,5+….+M1,Width−1*NWidth−1,5

在这种一一对应的映射下，线程索引 row 和 col 同时也是其输出元素的行索引和列索引。图 3.11 给出了基于这一线程-数据映射的核函数源代码。读者应当立刻看出熟悉的模式：计算 row 和 col（第 03–04 行），以及用 if 语句检测 row 和 col 是否都在范围内（第 05 行）。这些语句与 colorToGrayscaleConversion 中的对应语句几乎完全相同。唯一显著的差别在于，我们做了一个简化假设：matrixMulKernel 只需处理方阵，因此把 width 和 height 都替换为 Width。这种线程-数据映射实际上把 P 划分为若干分块，其中之一在图 3.10 中显示为浅色方块。每个线程块负责计算其中一个分块。

现在我们把注意力转向每个线程所做的工作。回想一下，Prow,col 是作为 M 的第 row 行与 N 的第 col 列的内积计算出来的。在图 3.11 中，我们用一个 for 循环来执行这一内积运算。进入循环之前，我们把局部变量 Pvalue 初始化为 0（第 06 行）。循环的每次迭代访问 M 的第 row 行中的一个元素和 N 的第 col 列中的一个元素，把两个元素相乘，并将乘积累加到 Pvalue 中（第 08 行）。

我们先关注 for 循环中对 M 元素的访问。M 按行主序布局线性化为一个等价的 1D 数组。也就是说，M 的各行从第 0 行开始，在内存空间中依次排列。因此第 1 行的起始元素是 M[1*Width]，因为需要先计入第 0 行的全部元素。一般而言，第 row 行的起始元素是 M[row*Width]。由于一行中的所有元素都存放在连续位置上，第 row 行的第 k 个元素位于 M[row*Width+k]。图 3.11（第 08 行）中使用的正是这一线性化数组偏移量。

现在我们把注意力转向对 N 的访问。如图 3.11 所示，第 col 列的起始元素就是第 0 行的第 col 个元素，即 N[col]。要访问第 col 列中的下一个元素，需要跳过一整行，这是因为同一列的下一个元素就是下一行中的相同元素。因此，第 col 列的第 k 个元素是 N[k*Width+col]（第 08 行）。

执行退出 for 循环后，所有线程的 P 元素值都保存在各自的 Pvalue 变量中。随后，每个线程使用等价的 1D 索引表达式 row*Width+col 写入自己的 P 元素（第 10 行）。同样，这种索引模式与 colorToGrayscaleConversion 核函数中所用的相似。

下面我们用一个小例子来说明矩阵乘法核函数的执行过程。图 3.12 给出了一个 BLOCK_WIDTH=2 的 4×4 的 P。虽然这样小的矩阵和线程块规模并不现实，但它们使我们能够把整个例子放进一幅图中。P 矩阵被划分为四个分块，每个线程块计算一个分块。为此，我们创建由 2×2 线程数组构成的线程块，每个线程计算一个 P 元素。在这个例子中，线程块 (0,0) 的线程 (0,0) 计算 P0,0，而线程块 (1,0) 的线程 (0,0) 计算 P2,0。

matrixMulKernel 中的 row 和 col 索引标识线程所要计算的 P 元素。row 索引同时标识 M 的行，col 索引标识 N 的列，二者作为该线程的输入值。图 3.13 说明了每个线程块中的乘法操作。对于这个小型矩阵乘法例子，线程块 (0,0) 中的线程产生四个点积。线程块 (0,0) 中线程 (1,0) 的 row 和 col 索引分别为 0*0+1=1 和 0*0+0=0。因此该线程映射到 P1,0，并计算 M 的第 1 行与 N 的第 0 列的点积。

让我们逐步走一遍线程块 (0,0) 中线程 (0,0) 对图 3.11 中 for 循环的执行过程。在第 0 次迭代（k=0）时，row*Width+k=0*4+0=0，k*Width+col=0*4+0=0。因此所访问的输入元素是 M[0]和 N[0]，它们是 M0,0 和 N0,0 的 1D 等价形式。注意，它们确实是 M 第 0 行和 N 第 0 列的第 0 个元素。在第 1 次迭代（k=1）时，row*Width+k=0*4+1=1，k*Width+col=1*4+0=4。因此我们访问的是 M[1]和 N[4]，它们是 M0,1 和 N1,0 的 1D 等价形式。它们是 M 第 0 行和 N 第 0 列的第 1 个元素。在第 2 次迭代（k=2）时，row*Width+k=0*4+2=2，k*Width+col=2*4+0=8，由此得到 M[2]和 N[8]。因此所访问的元素是 M0,2 和 N2,0 的 1D 等价形式。最后，在第 3 次迭代（k=3）时，row*Width+k=0*4+3=3，k*Width+col= 3*4+0=12，由此得到 M[3]和 N[12]，即 M0,3 和 N3,0 的 1D 等价形式。至此我们已经验证，对于线程块 (0,0) 中的线程 (0,0)，该 for 循环执行的是 M 的第 0 行与 N 的第 0 列之间的内积。循环结束后，该线程写入 P[row*Width+col]，即 P[0]。这是 P0,0 的 1D 等价形式，因此线程块 (0,0) 中的线程 (0,0) 成功计算了 M 的第 0 行与 N 的第 0 列之间的内积，并把结果存入 P0,0。

我们把手工执行并验证线程块 (0,0) 中其他线程或其他线程块中线程的 for 循环，留作读者的练习。

由于网格的大小受每个网格的最大线程块数和每个线程块的最大线程数限制，matrixMulKernel 所能处理的最大输出矩阵 P 的规模也会受到这些约束的限制。当需要计算超出该限制的输出矩阵时，可以把输出矩阵划分为若干子矩阵，使每个子矩阵的规模都能被一个网格覆盖，并用主机代码为每个子矩阵启动一个不同的网格。另一种做法是修改核函数代码，让每个线程计算更多的 P 元素。本书后面将探讨这两种方案。

3.5 小结

CUDA 的网格和线程块是多维的，最多可达三维。网格和线程块的多维性便于组织线程，使其映射到多维数据上。核函数执行配置参数定义网格及其线程块的维度。blockIdx 和 threadIdx 中的唯一坐标使网格中的线程能够标识自身以及各自的数据域。程序员有责任在核函数中使用这些变量，以便线程能够正确地确定所要处理的那部分数据。在访问多维数据时，程序员往往必须把多维索引线性化为一个 1D 偏移量，原因是 C 语言中动态分配的多维数组通常按行主序布局存储为 1D 数组。我们使用复杂度递增的例子，让读者熟悉用多维网格处理多维数组的具体机制。这些技能将是理解并行模式及其相关优化技术的基础。
