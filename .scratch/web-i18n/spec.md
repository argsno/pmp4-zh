# Spec: 中文版与中英对照版站点

**Labels:** `ready-for-agent`

---

## Problem Statement

《Programming Massively Parallel Processors》第 4 版已经被 `build_site.py` 从 EPUB 转换成一个可浏览的英文静态站点，共 38 个页面。但它只有英文。

中文读者要学 CUDA / GPU 并行编程，面对的是约 120 万字符的英文技术散文。逐段查词的阅读速度慢到让人放弃；而纯中文译本又切断了读者与原书术语、与英文文档、与教授在课堂上使用的原始表述之间的联系——读者需要在"读得快"和"对得上"之间二选一。

仓库里已经有一份写得相当细的 `TRANSLATION_STANDARDS.md`，规定了术语表、HTML 处理规则、标点排版规范，但没有任何译文，也没有任何把译文变成站点的机制。任何人想开始翻译，都得先面对一个更棘手的问题：这些页面是 Elsevier 导出的 XHTML，里面有 MathML 公式、`<pre>` 片段、2888 个交叉引用 `<a>`、2544 个句中零宽 pagebreak `<span>`。直接编辑 HTML 翻译，几乎必然会在某处弄坏标签、丢掉锚点、破坏排版，而且坏在哪里没人看得出来。

## Solution

在保留现有英文站点完全不变的前提下，新增两套平行站点：

- **中文版** —— 正文全中文，导航、目录、按钮也全中文，供以中文为主的通读。
- **中英对照版** —— 每个段落英文在上、中文紧随其下，供需要核对原文措辞、记忆英文术语的精读。

两套站点由同一份译文数据机械渲染而成，翻译只做一次。读者可以在任意页面通过顶栏的 `EN / 中 / 对照` 按钮，原地切换到当前这一页的其他语言版本。

译文不再是"改过的 HTML"，而是独立的结构化数据，与页面结构解耦。渲染由脚本完成，并在渲染时执行一组硬性校验：占位符集合、块级节点数、`<pre>`/`<math>` 字节一致性等。任何一项不通过，该页面就不会被生成，而不是生成一个坏掉的页面。

## User Stories

### 中文读者

1. As a 中文读者, I want 每一章正文都有通顺准确的中文译本, so that 我能以母语速度理解 CUDA 编程概念，而不必逐句查词。
2. As a 中文读者, I want 术语在全书范围内译法一致, so that 我不会误以为"扫描"和"前缀和"是两个不同的概念。
3. As a 中文读者, I want 首次出现的术语以"线程束（warp）"形式中英并列, so that 我在读英文文档或论文时能把中文概念对上英文原词。
4. As a 中文读者, I want 顶栏的章节下拉列表是中文的, so that 我不用在中文正文和英文导航之间反复切换语言脑区。
5. As a 中文读者, I want 上一页/下一页/首页按钮是中文的, so that 整个阅读界面语言一致。
6. As a 中文读者, I want 中文版落地页的完整目录是中文的, so that 我能一眼扫到我想读的那一章。
7. As a 中文读者, I want 图题、表题、习题、摘要、关键词也都翻译, so that 我不会在正文读到一半撞上一段没译的英文。
8. As a 中文读者, I want 章节号、图号、表号、公式号保持原样, so that 我能和纸质英文原书、和课程讲义对上位置。
9. As a 中文读者, I want 中文与英文单词、数字之间有半角空格, so that 排版不挤，长句读起来不费力。
10. As a 中文读者, I want 数学公式原样保留, so that 公式渲染不出错，符号不被误改。
11. As a 中文读者, I want 所有图片、交叉引用链接、章节锚点都正常工作, so that 中文版是一个真正能用的站点而不是残缺的副本。

### 中英对照读者

12. As a 中英对照读者, I want 每个段落英文在上、中文在下, so that 我读完英文后能立刻验证自己的理解。
13. As a 中英对照读者, I want 中文译文有明显的视觉区分（左侧竖线、微灰底）, so that 我扫视页面时能一眼分清哪段是原文哪段是译文。
14. As a 中英对照读者, I want 标题也是英中两行, so that 章节结构在两种语言里都清晰。
15. As a 中英对照读者, I want 表格单元格内英中用换行分隔, so that 表格不会因为横向塞两种语言而撑破排版。
16. As a 中英对照读者, I want 图题英中两行, so that 我能对照理解图示说明。
17. As a 中英对照读者, I want 代码块和公式不被重复两遍, so that 页面不被无意义的重复内容拉长。
18. As a 中英对照读者, I want 对照版的章节下拉同时显示中英标题, so that 我在导航时也能建立中英对应。
19. As a 中英对照读者, I want 对照版在手机上仍然可读, so that 我能在通勤时用它精读。

### 跨版本导航

20. As a 读者, I want 在任意页面一键切到该页的其他语言版本, so that 我遇到难句时能立刻调出对照版，读顺了再切回中文版。
21. As a 读者, I want 切换语言后停留在同一章, so that 我不会被扔回首页重新找位置。
22. As a 读者, I want 每套站点的上一页/下一页只在本套站点内跳转, so that 我点了几次"下一页"之后不会莫名其妙回到英文。
23. As a 英文读者, I want 现有英文站点的行为、外观、链接完全不变, so that 这次改动不会破坏我已有的使用习惯和书签。

### 译者 / 维护者

24. As a 维护者, I want 译文以结构化数据形式独立存放, so that 重新运行 `build_site.py` 从 EPUB 重建站点时译文不会丢失。
25. As a 维护者, I want 一条命令重建三套站点, so that 我不需要记住多步骤流程。
26. As a 维护者, I want 译文数据纳入版本控制, so that 我能 diff、review、回滚单个段落的译法。
27. As a 维护者, I want 单个段落的修订只影响该段落, so that 我改一个词不会导致整页重新生成出巨大的 diff。
28. As a 维护者, I want 结构性错误在渲染时被拦截而不是流到站点上, so that 我不必靠肉眼在 120 万字符里找哪个标签丢了。
29. As a 维护者, I want 校验失败时能精确知道是哪一页的哪一个节点、违反了哪一条, so that 我能定点修复而不是重跑整章。
30. As a 维护者, I want 术语表在翻译开始前就扩充完整并经我过目, so that 我不必在 32 页译完之后再回头统一术语。
31. As a 维护者, I want 翻译过程中发现的表外新词被记录下来, so that 我能在收尾时把它们合并回术语标准。
32. As a 维护者, I want 中英空格规则由脚本机械执行, so that 一致性不依赖每个译者的自觉。
33. As a 维护者, I want 翻译工作可以按页中断和续跑, so that 中途失败不会浪费已完成的部分。
34. As a 维护者, I want 参考文献条目保留英文原文, so that 读者能据此检索到真实文献。
35. As a 维护者, I want `TRANSLATION_STANDARDS.md` 中被本次实践推翻的条款同步修订, so that 标准文件与实际做法不脱节。

### 工程质量

36. As a 开发者, I want 一个回归测试证明"译文等于原文时渲染结果与英文原页逐字节相同", so that 我确信抽取没有漏内容、回填没有丢内容。
37. As a 开发者, I want 占位符不匹配的译文被判定为违规, so that 内联标签错位不会悄悄进入站点。
38. As a 开发者, I want 不可译内容（代码块、公式、参考文献）永远不进入抽取结果, so that 翻译者不会误改它们。
39. As a 开发者, I want 所有测试通过单一接口驱动, so that 测试不与内部实现细节耦合，重构时不会大面积失效。

## Implementation Decisions

### 站点布局

三套并列的站点树，共用同一份 `images/` 与 `styles/`：

- `web/chapters/` —— 英文，现状不变
- `web/zh/chapters/` —— 纯中文
- `web/bilingual/chapters/` —— 中英对照

各版本有自己的 `index.html` 落地页。新增一份中文排版样式表（中文字体栈、行高、`.zh-trans` 对照样式）。

选择三套目录而非单套页面内嵌双语 + 前端切换：前者不改动现有英文页面、可独立部署、无 JS 依赖；后者会使单页体积翻倍并改写既有产物。

### 译文数据存储

译文存于仓库根的 `translations/`，按页分目录、页内分片：

```
translations/<page-stem>/part-00.json
translations/<page-stem>/newterms.json
```

分片文件的形态：

```json
{
  "page": "<page-stem>",
  "nodes": [
    {
      "id": "p0085",
      "path": "<稳定定位符>",
      "en": "Data parallelism refers to 【1】the phenomenon【/1】 in which…",
      "zh": "数据并行指的是【1】这样一种现象【/1】：…"
    }
  ]
}
```

分片存在的理由有两条：翻译 Agent 单次输出不会因页面过大而截断；中途失败可从已落盘的分片续跑。

`translations/` 与生成的两套站点均纳入 git —— 与现有"英文 `web/` 已入库"的做法保持一致，使站点可直接部署。

### 渲染模块

新增 `build_i18n` 模块，对外暴露一个核心函数：

```
render(page_html: str, translations: dict) -> RenderResult
    .zh_html: str | None
    .bilingual_html: str | None
    .violations: list[Violation]
```

抽取、占位符映射、回填、对照交错、空格规范化、全部硬校验都在这个边界之内。`violations` 非空时对应的输出为 `None` —— 坏页面不生成，而不是生成坏页面。

模块另提供命令行入口，用于抽取空译文骨架、渲染全站、单独跑校验。

`build_site.py` 在末尾调用它，使"重建英文站点"与"重建三套站点"成为同一条命令。这条依赖方向是单向的：`build_i18n` 不知道 `build_site.py` 的存在。

### 抽取规则

**抽取**：`p`、`li`、`h1`–`h4`、`figcaption`、`td`、`th`、`caption`

**不抽取**：

- `pre` —— 全站 39 个，均为 `float *A_d` 这类行内片段，无一含代码注释。`TRANSLATION_STANDARDS.md` §6.3 "代码注释可译"在本书是空条款，因为**全书代码清单是图片**。
- `math` —— MathML 整体原样保留
- `p.reflist3[role=doc-biblioentry]` —— 参考文献整条保留英文（§4.8）
- `header.topnav` —— 由渲染器自己生成，不走译文数据

### 占位符文法

内联标记以占位符形式呈现给翻译者，翻译者永远不接触真实标签或属性：

- 成对标签（`em` / `strong` / `a[href]` / `cite` / `sub` / `sup`）→ `【N】文本【/N】`，翻译者需把它搬到对应的中文词上
- 原子块（`math` / `pre` / `img`）→ `【MN】`，不可拆分、不可翻译
- 零宽空元素（`a[id]` 锚点、pagebreak `span`）→ 抽取时剥离，回填时统一置于节点首

最后一条有一个可见代价：句中的页码锚点位置会移到段首。因为它们是零宽元素，视觉上不可察觉，但用页码锚点做深链接时会有轻微偏移。这是为了让翻译者面对的是近乎纯文本、从而使占位符校验可以做成严格相等判定，所付出的代价。

### 校验（硬门槛）

任一项失败，该页不生成：

1. 译文占位符集合与原文**完全相等**（不可增、不可删、不可改编号）
2. 生成页的块级节点数与英文页一致
3. 生成页可被解析器解析
4. `pre` / `math` 的序列化结果与英文页**逐字节相同**
5. 译文非空且含中日韩字符（拦截漏译与原样复制）
6. 命中术语表的英文词，其中文译法与术语表一致

### 排版约定

- 对照版：每个块级节点复制一份，英文在上（原样），中文紧随其下带 `zh-trans` 类；标题的中文行字号略小；表格单元格内以换行分隔；`pre` / `math` / 参考文献不复制
- 中英、中数之间统一半角空格；中文标点两侧不加。此规则由渲染器机械执行并自动修正，不依赖翻译者自觉
- 中文版导航：章节标题取自译文数据，`option` 的 `value` 属性绝不改动；对照版导航中英并列

### 术语表

先扩充后翻译。`TRANSLATION_STANDARDS.md` §5 目前约 70 条，缺失全书大量核心概念（scan / prefix sum、reduction、histogram、stencil、sparse matrix 与 CSR/ELL/JDS/COO、merge、BFS、dynamic parallelism、stream、privatization、atomic operation、pinned memory、pooling 等）。由一个专门的扫描任务先扩充到约 250 条，经维护者过目后冻结。

翻译任务对术语表**只读**。表外新词写入本页的 `newterms.json`，收尾时统一合并。这条约束的直接原因是并发：多个翻译任务同时写同一个标准文件必然互相覆盖。

### 翻译任务的执行契约

每页一个子任务，并发 4。每个子任务：

- 只读 `TRANSLATION_STANDARDS.md` 与本页的英文抽取结果
- 每约 25 个节点落盘一个分片
- 只填 `zh` 字段，不碰 `en`、`id`、`path`
- 表外新词写入本页 `newterms.json`
- **绝不编辑任何共享文件**

校验失败的节点回传同一子任务重译，最多 2 轮；仍失败则停止并报告，不静默降级。

### 需同步修订的标准条款

- §4.6 "导航栏暂保留英文，待全书译毕后再统一中译" —— 本次即为全书译毕，改为记录现行做法（`value` 不动、显示文本中译）
- §6.2 "数字与中文之间加不加空格全书统一即可" —— 该口子在并发翻译下必然产生不一致，收紧为强制规则

### 已知且接受的损失

全书代码清单与流程图共 613 张图片、357 个 `figure`，图内英文文字无法翻译，中文版读者看到的代码仍是英文图片，只有图题中译。OCR 重绘 357 张图不在合理成本范围内。

## Testing Decisions

### 什么算好测试

只测外部行为，不测内部实现。测试断言的对象是**渲染产物的性质**与 `violations` 的内容，而不是"抽取函数返回了几个节点""某个内部字典长什么样"。抽取策略、占位符编号方式、遍历顺序都应当可以自由重构而不导致测试失效。

### 单一 seam

全部测试通过 `render(page_html, translations)` 驱动。这是能取到的最高接缝，覆盖抽取、占位符映射、回填、对照交错、空格规范化与全部校验。

明确拒绝的更低接缝：

- 分别测 `extract()` 与 `inject()` —— fixture 数量翻倍，且两者会各自演化到不兼容而测试仍然全绿
- 在命令行 / 文件系统层测 —— 慢，断言笨拙，且把 I/O 编排的偶然细节固化进测试

### 测试清单

**旗舰测试 —— 往返 identity**：从一个真实章节页抽取，对每个节点填入 `zh == en`，渲染中文版，断言输出与英文原页逐字节相同（顶栏与 `lang` 属性除外）。这一个测试同时证明抽取覆盖了全部可译内容、回填没有丢失任何东西、`pre` / `math` / 属性 / 锚点全部原样存活。它是这套测试里最有价值的一条。

围绕同一接缝的其余测试：

- 占位符搬移：含 `em` / `a` / 嵌套标记的段落，译文中占位符位置改变 → 生成正确的 HTML，标签落在中文词上
- 占位符缺失、多余、编号错乱、不闭合 → 各自产生 violation，且该页不生成
- 不可译内容：`pre`、`math`、`p.reflist3` 从不出现在可译节点中，且在产物中原样存在
- 零宽元素：pagebreak `span` 与 `a[id]` 数量在产物中不变
- 对照版：块级节点数翻倍、`zh-trans` 存在、`pre` 与参考文献**不**翻倍
- 空格规范化：`使用CUDA编程` → `使用 CUDA 编程`；中文标点两侧不加空格
- 漏译与原样复制：空 `zh`、纯英文 `zh` → violation
- 导航本地化：`option` 的 `value` 不变，显示文本已中译

### 先决条件

仓库目前没有任何测试基础设施（无 pytest、无 pyproject、无 tests 目录），`lxml` 已可用。本 spec 需引入 pytest 与一个 `tests/` 目录。**没有现成的测试先例可循** —— 本次建立的形态将成为该仓库后续测试的先例，因此 fixture 的组织方式应当刻意保持简单：真实章节页作为大 fixture 供 identity 测试使用，手写的小段 HTML 供各项单点行为使用。

### 非自动化的验收

维护者人工抽查两页：风格基准页（第 1 章）与结构最复杂页（第 16 章，261 个块级节点、图表公式最密集）。其余页面仅靠机检。

## Out of Scope

- **纯索引类页面**：`Index`（4 万字符纯页码索引，译后需重新排序且价值低）、`Contents` 与 `nav`（由 `build_site.py` 生成，应改脚本而非翻译）、`Cover`、`Copyright`（版权页有法律风险）、`Title_page`
- **图内文字翻译**：357 张代码清单与流程图保持英文
- **参考文献条目本身**：保留英文原文（§4.8）
- **EPUB 回写**：不生成中文版 EPUB，只做站点
- **翻译记忆库 / 机器翻译 API 集成**：本次由子任务直接产出译文
- **繁体中文、其他语种**：架构上支持扩展，本次不做
- **英文站点的任何行为变更**：除新增语言切换按钮外不动
- **全文搜索、术语索引页、译文批注系统**等阅读增强功能

## Further Notes

**先决动作**：仓库目前**零 commit**，所有内容仅处于 staged 状态。本工作会新增约 1.2 MB 译文数据与约 6 MB 生成页面，且回填脚本会批量写文件。开工前必须先把现有内容提交为初始 commit，并把 `__pycache__` 移出索引、加入 `.gitignore`。没有这一步就没有任何回滚点。

**两道卡点**（其余环节不打断维护者）：

1. 术语表扩充至约 250 条后，等维护者过目冻结
2. 首批 4 页译完并生成三套页面后，等维护者在浏览器中确认译文风格与对照排版

首批 4 页刻意选取覆盖不同形态：风格基准章、图表密集章、节点数最多章、以及文体不同的前言。

**规模参考**：32 个页面，约 119 万字符英文正文，3244 个块级节点，其中 73% 含内联标记（2888 个 `a`、2544 个 `span`、1000 个 `em`、75 个内联 `math`）。

**方法论要点**：本方案的核心判断是——让语言模型直接编辑 Elsevier 导出的 XHTML 是不可靠的，而让它填写纯文本字段、由确定性脚本还原结构是可靠的。所有关于占位符、分片、只读术语表、硬校验的设计，都是这一判断的推论。
